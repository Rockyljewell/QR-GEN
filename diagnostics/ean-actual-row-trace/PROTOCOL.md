This study instruments the unchanged ZXing-C++ release policy. It does not test or select a recognition filter. The known photographs and earlier results were seen before this protocol; this is a diagnostic investigation, not a held-out accuracy benchmark.

Freeze 15 existing rasters before any recognition: original and derived `/1/35`, derived `/2/07`, actual Chrome `/2/07`, all nine saved physical-feasibility controls, and original `/2/14` and `/2/20`. Cross each with fast/hard search and maximum symbols 1/2/255: exactly 90 profiles. The fixed settings are EAN13, rotate enabled, native inversion disabled, downscale disabled, denoise disabled, non-pure input, minimum two accepted lines, ignored add-ons, no returned errors, LocalAverage binarizer, HRI text. No new fixture generation, cropping, threshold selection, payload replacement, or recognition-policy change is authorized by this protocol.

Use the exact existing lossless PNG transports from the public Node study, where available. Verify PNG bytes, decoded RGBA bytes and dimensions against the earlier frozen identities. Verify all nine controls against their original control manifest. Keep source-file identity separate from transport identity. No reader import or recognition occurs during preparation.

Build an unmodified-policy baseline and an instrumented copy from wrapper `b7dcf63aefc7b94fb97ba09e9b1fb213d9399f54`, C++ `2ecec3f5be0ee803f6e14a5a2c7028c0cfe525b4`, emsdk 5.0.4 and pnpm 12.8.2. The trace patch targets the upstream C++ baseline, not the earlier whole-word-ambiguity candidate. The baseline gets no patch or diagnostic definition. The trace copy receives only this patch and `ZXING_QRGEN_ROW_TRACE=1`. Retain exact applied patches, source hashes, compiler flags/cache, matching full ES reader graph, Emscripten glue, WASM hashes and successful workflow provenance. Parent binds the compiled builds to the frozen plan before recognition.

First gate: execute all 90 paired profiles using matching isolated baseline and trace wrapper graphs, exact frozen pixels and options. Compare ordered result arrays with every own string property recursively, including typed-array bytes and symbol rasters. Reject unexpected symbol properties, accessors or non-finite numbers. Check input-buffer immutability. Capture the trace records during these same calls, but do not interpret their payloads or scheduling until all 90 public-output comparisons pass. On the first mismatch, preserve both exact recorded values and diagnostics, stop further recognition and mark conformance failed. Reader errors and malformed trace transport are separately recorded failures, never silently skipped. A changed diagnostic source line counts as a public-output mismatch in this protocol. `returnErrors:false` is fixed.

Trace scope: original/layer dimensions and bitmap pass; row scheduling and additional check rows; binarizer threshold/histogram and row rejection; both directions; complete run lengths; guard-test returned values and exit sites; each UPC/EAN parsing check rejection; digit-pattern variances with exact float32 bits, selected pattern and thresholds; parity, checksum and provisional/final formats; final consumed cursor; collector comparison/insert/merge/support/overlap-discard and stable group IDs; orientation gates and budget exits; sorted/global output positions and duplicate handling. For full resolution the row-direction record gives the exact affine map `(originX,originY)+(xStep,yStep)*scanX` into original image coordinates. Returned positions remain scanline-support envelopes. They are not physical bar boundaries.

Every call is bounded to 250,000 ordinary trace records, 32 MiB ordinary stderr bytes and 16,384 bytes per event. The final call-end marker is outside the ordinary cap and reports omitted/oversized counts. Collector IDs have a capacity of 8,192 live groups. A cap hit, missing call-end, gap in sequence numbers, malformed record, unrecognised stderr line, or nonzero dropped/oversized count makes the trace incomplete. Recognition must continue under its original policy when the C++ transport drops records. The runner imposes an independent host transport cap and never throws from printErr into recognition.

Interpretation after conformance: reconstruct the actual attempted rows, decode attempts, accepted groups and group transitions for each exact profile. Explain why max1/max2/max255 differ only where the retained trace directly supports it. Preserve paired identities/counts for the same-payload two-label control. Do not substitute majority support or expected truth for a decoding decision. Compare legitimate aligned/nearby labels and white-band controls before proposing any physical identity experiment. Any future policy must be frozen separately with independent controls; this study selects no threshold or rule.

Limitations: instrumentation changes execution time and code layout; output equivalence is a necessary gate, not a proof for all inputs or modes. Only the 90 frozen profiles are covered. Rejected candidates are observed only at the existing guards/parser paths; no alternate digit search is added. Non-finite diagnostic real values use explicit JSON strings (NaN, +Infinity, -Infinity), with exact float32 score bits and float64 guard-result bits retained. Digit scores capture the original matching operation, not a new enumeration of complete valid words. Generic matrix readers, camera capture, native builds, downscale/inversion modes, UPC-only aliases and add-on modes are outside this matrix. No complete physical-support mask is exposed by this trace. Source expressions and coordinates beyond these hooks must not be presented as measured scheduling. No Scandit comparison follows from this study.
